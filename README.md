# RangerPython

A Python runtime written in [Ranger](https://github.com/terotests/Ranger). It
runs Python 3 scripts on an in-memory filesystem, so a page (Sliqtly), a
Node tool or an AI agent can run a script that reads the files it is given
and writes new ones (an SVG chart, a CSV), and then take those files back.

The same source compiles to JavaScript (browser and Node), Go and Python;
the test suite runs on all three and compares each against CPython.

```js
import { runPython } from "ranger-python";

const r = runPython(source, { files: { "/data/sales.csv": csvText } });
r.ok          // false when the script raised
r.stdout      // what it printed
r.files       // { "/tmp/chart.svg": "<svg …" }  the files it wrote
r.traceback   // CPython-style report when it raised
```

## Hooking into a host filesystem

`js/host.mjs` runs a script against files the host keeps. The host gives
three functions, any of them async:

```js
import { runOnHost } from "ranger-python/host";
const r = await runOnHost(code, {
  list: () => ({ "/data/sales.csv": csvText }),   // the files to mount
  write: (path, text) => save(path, text),         // each file the script wrote
  remove: (path) => drop(path),                     // each mounted file it deleted
});
```

The files are copied in before the run and the changes handed back after
it, so the script never waits on the host, and the same script runs in a
Worker (`{ run: workerRunner(worker) }`, see `js/worker.mjs`).

## Sliqtly

`js/sliqtly.mjs` is that interface over Sliqtly's store (`web/vfs.js`):

```js
import { runInDeck } from "ranger-python/sliqtly";
const r = await runInDeck(vfs, doc.id, code);
r.saved   // [{ from: "/tmp/chart3d.svg", path: "media/chart3d.svg" }]
```

- The deck's text files are mounted at the root: `data/sales.csv` is
  `/data/sales.csv` (and `data/sales.csv` from the working folder `/`).
- A file the script writes in a deck folder (`media/`, `data/`, `charts/`,
  `apps/`) is saved there; any other path (`/tmp/chart3d.svg`) is saved by
  its name where Sliqtly puts that kind of file (`media/chart3d.svg`). Pass
  `place` to choose differently.
- A deck file the script deletes is deleted from the deck.
- `js/worker.mjs` runs scripts in a Worker so a long script does not block
  the page: `runInDeck(vfs, id, code, { run: workerRunner(worker) })`.

## Command line

```
node js/cli.mjs script.py [args…] [--mount DIR] [--max-steps N]
```

With `--mount`, DIR is the filesystem's root and what the script wrote is
saved back into DIR.

## How much of Python runs

Three measures, each regenerated by a script:

- [docs/FEATURES.md](docs/FEATURES.md): 102 short programs, one per
  language feature or module, compared with CPython's output on the
  JavaScript, Go and Python builds (`node tests/features/run.mjs --go --python`).
- [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md): CPython 3.13's own test
  suite (`Lib/test`, 64 files), counting the test methods that pass here
  out of those that pass on CPython (`node tests/conformance/run.mjs`).
- [docs/BENCHMARKS.md](docs/BENCHMARKS.md): speed against CPython on six
  small programs (`node tests/bench/run.mjs --go`).

The language: functions (defaults, `*args`, `**kw`, keyword-only and
positional-only), closures, `global`/`nonlocal`, lambdas, decorators,
classes with inheritance, `super()`, metaclasses, descriptors, `__slots__`,
properties, operator overloading and the other dunder protocols, exceptions
with `try`/`except`/`except*`/`else`/`finally`, `raise from`, exception
groups, `with`, generators (lazy, with `send`/`throw`) and `yield from`,
comprehensions, `match`, f-strings, `%` formatting, `str.format`, slicing,
unpacking, the walrus operator, complex numbers, `import` of `.py` files in
the filesystem.

Number formatting (`repr` of floats, `:.2f`, `:g`, `:e`, grouping) is
correctly rounded and matches CPython.

Modules: `math`, `random` (CPython's Mersenne Twister: a seeded
script draws the same numbers), `json`, `csv`, `re`, `os`, `os.path`,
`sys`, `string`, `time`, `collections` and `collections.abc`, `itertools`,
`functools`, `operator`, `statistics`, `copy`, `typing`, `dataclasses`,
`enum`, `abc`, `fractions`, `decimal` (simple), `heapq`, `bisect`,
`textwrap`, `io.StringIO`, `contextlib`, `inspect`, `unittest` and
`unittest.mock`, `traceback`, `warnings`, `weakref`.

Files: `open` in modes `r`, `w`, `a`, `x`, text only; `os.listdir`,
`makedirs`, `remove`, `rename`, `walk` and the `os.path` functions.

Limits: `maxSteps` stops a runaway script; deep recursion stops with
`RecursionError`.

## What does not run

- Integers are exact up to 2^53 on the JavaScript build (64-bit on Go); there
  are no big integers.
- No `bytes`/`bytearray` (a `b"…"` literal is a `str`), no binary files, so
  no `struct`.
- No `async`/`await` event loop (`asyncio`), no `datetime`.
- The interpreter walks the syntax tree: it runs 7 to 15 times slower than
  CPython on the JavaScript build and 16 to 41 times on Go (see
  docs/BENCHMARKS.md).

## Building and testing

```
npm ci
npm test            # build dist/ and run the suite on the JavaScript build
npm run test:all    # also the Go and Python builds (needs go and python3)
node tests/run.mjs --update   # re-record tests/expected from CPython
```

`dist/pyruntime.mjs` (ESM) and `dist/pyruntime.cjs` are committed so the
runtime can be used without the Ranger compiler; CI checks they are the
build of `src/`.

The source, in `src/`:

| file | |
|---|---|
| `PyLexer.rgr`, `PyParser.rgr`, `PyAst.rgr` | tokens, indentation, the syntax tree |
| `PyInterp.rgr` | the tree-walking evaluator |
| `PyValue.rgr` | values and scopes |
| `PyBuiltins.rgr` | built-in functions and exception classes |
| `PyMethods.rgr` | methods of str, list, dict, set, file, … |
| `PyModules.rgr` | the standard library modules |
| `PyFormat.rgr` | number and string formatting |
| `PyFs.rgr` | the in-memory filesystem |
| `PyOps.rgr` | host operations per target |
| `PyRuntime.rgr` | the public API |
| `PyMain.rgr` | command line runner for the Go and Python builds |
